# 1. PROJECT OVERVIEW

## 1.1 Project Name

**Lakshya** (लक्ष्य)

**Meaning:** "Target" or "Goal" in Hindi/Sanskrit

**Tagline:** "Your Goal, Your Path, Your Success"

---

## 1.2 One-Line Elevator Pitch

**Lakshya is an AI-powered productivity platform specifically designed for Indian students to transform their academic and career goals into actionable, personalized roadmaps with integrated task management, smart scheduling, and data-driven insights.**

---

## 1.3 Problem Statement

### The Challenge

Indian students face immense pressure to excel in competitive environments:

- **GATE/JEE Exams:** ~10 lakh students compete annually for limited seats
- **Campus Placements:** Pressure to master DSA + system design + projects in 6-12 months
- **Startup Ambitions:** Lack of structured approach to build MVPs and launch
- **Higher Studies:** GRE/TOEFL prep + applications while managing current coursework
- **Skill Development:** Need to learn new technologies but overwhelmed by resources

### Core Problems

1. **Goal Paralysis:** Students know what they want but don't know where to start
2. **Poor Planning:** No structured breakdown of large goals into actionable tasks
3. **Scattered Tools:** Using 5+ apps (Notion, Google Calendar, Pomodoro apps, task lists)
4. **No Personalization:** Generic productivity advice doesn't fit Indian student context
5. **Lack of Accountability:** No system to track progress or adjust plans
6. **Time Mismanagement:** Classes + assignments + exam prep = chaos

### Statistics

- **40M+** students in Indian higher education
- **60%** feel overwhelmed by academic pressure (NCERT survey)
- **70%** of students use multiple disconnected productivity tools
- **35%** of GATE aspirants fail to complete syllabus due to poor planning

# 3. TECHNICAL APPROACH

## 3.1 Technology Stack

### Frontend

- **Framework:** Next.js 16 (App Router with React Server Components)
- **Language:** TypeScript 5
- **Styling:** Tailwind CSS 4
- **UI Components:** shadcn/ui (Radix UI primitives)
- **State Management:** Zustand (client state), React Server Components (server state)
- **Charts:** Recharts
- **Calendar:** react-big-calendar
- **Rich Text Editor:** Tiptap
- **Icons:** Lucide React
- **Animations:** Framer Motion

**Why These Choices:**
- **Next.js 16:** Server components for performance, SEO, API routes for backend
- **TypeScript:** Type safety, better developer experience, fewer runtime errors
- **Tailwind:** Rapid UI development, consistent design system, no CSS bloat
- **shadcn/ui:** Accessible, customizable, no bundle size overhead
- **Zustand:** Lightweight (1KB), simple API vs Redux complexity

---

### Backend
- **Runtime:** Next.js API Routes & Server Actions
- **Database:** PostgreSQL (Supabase)
- **Authentication:** Supabase Auth
- **Storage:** Supabase Storage (for future file uploads)

**Why These Choices:**
- **Next.js API Routes:** Serverless, auto-scaling, same codebase as frontend
- **PostgreSQL:** ACID compliant, supports complex queries, JSON fields
- **Supabase:** Managed Postgres + Auth + Storage + Realtime in one platform

---

### AI
- **Model:** Google Gemini 3.5 Flash Lite
- **Use Cases:** Roadmap generation, daily recommendations

**Why Gemini:**
- Free tier with generous limits (1500 req/day)
- Fast response times (<5s for roadmap)
- Structured JSON output support
- Better at understanding Indian context vs GPT


---

### Deployment
- **Hosting:** Vercel (frontend + API routes)
- **Database:** Supabase Cloud
- **CI/CD:** Vercel automatic deployments on git push

**Why Vercel:**
- Optimized for Next.js
- Edge functions for low latency
- Free tier sufficient for MVP
- GitHub integration for auto-deploy

## 3.3 Data Flow

### Example: AI Recommendation Generation

```
1. User clicks "Refresh" on Dashboard AI Recommendations widget
   ↓
2. Client sends GET /api/ai/recommendations
   ↓
3. API route authenticates user (Supabase Auth)
   ↓
4. Fetch user's pending tasks (status != completed)
   ↓
5. Fetch today's calendar events to calculate free time
   ↓
6. Fetch goal progress and milestones
   ↓
7. Send context to Gemini AI:
   - Prompt: "Analyze pending tasks, free time (5-9 PM), goal progress"
   - Model: gemini-3.5-flash-lite
   ↓
8. Gemini returns 3-5 recommendations (JSON)

   ↓
9. API route returns recommendations to client
   ↓
10. Client updates UI with new recommendations
```

## 3.4 Database Design

### Core Tables (9 Tables)

1. **users** - User profiles (extends Supabase auth.users)
2. **goals** - Primary student goals
3. **milestones** - Goal breakdown into phases
4. **tasks** - Actionable tasks
5. **notes** - Rich text notes
6. **timetable_events** - Calendar events
7. **timetable_slots** - Class schedule
8. **pomodoro_sessions** - Study session history
9. **analytics_events** - Activity tracking

### Key Relationships

```
users (1) ──→ (M) goals
goals (1) ──→ (M) milestones
goals (1) ──→ (M) tasks
milestones (1) ──→ (M) tasks
users (1) ──→ (M) notes
users (1) ──→ (M) timetable_events
tasks (1) ──→ (0..1) timetable_events (scheduled tasks)
```

### Security: Row Level Security (RLS)

**Every table has policies:**
- Users can only SELECT their own data
- Users can only INSERT/UPDATE/DELETE their own data
- No cross-user data leakage

**Example Policy:**
```sql
CREATE POLICY "Users can view their own tasks"
  ON tasks FOR SELECT
  USING (auth.uid() = user_id);
```

## 3.5 Authentication Flow

```
1. User visits /login or /signup
   ↓
2. Enters email + password
   ↓
3. Next.js calls Supabase Auth API
   ↓
4. Supabase validates credentials

   ↓
5. Returns JWT token + session
   ↓
6. Next.js sets httpOnly cookie
   ↓
7. Redirects to /goals (goal selection) or /dashboard
   ↓
8. Middleware checks auth on every request
   ↓
9. If no valid session → redirect to /login
```

---

## 3.6 Security Considerations

### 1. Authentication
- JWT tokens stored in httpOnly cookies (XSS protection)
- Session-based auth with automatic refresh
- Password hashing by Supabase (bcrypt)

### 2. Authorization
- Row Level Security on all tables
- API routes validate user ownership
- No direct database access from client

### 3. API Security
- Rate limiting (Vercel limits)
- Input validation with Zod schemas
- SQL injection prevention (parameterized queries via Supabase SDK)

### 4. Data Privacy
- No PII shared with Gemini AI (only task titles, not user emails)
- AI responses cached to reduce API calls
- User data isolated per account

## 6.2 Challenges & Mitigation

### Challenge 1: AI API Costs at Scale

**Risk:** Gemini API has free tier (1500 req/day). At 10K users, could exceed.

**Mitigation:**
- Cache AI recommendations for 4 hours
- Rate limit: 3 recommendations/user/day
- Fallback to rule-based suggestions if API fails
- Gemini pricing: $0.000125/1K chars input (very affordable)
- **Estimated cost:** 10K users × 3 rec/day = 30K requests/day = ~$15/month

---

### Challenge 2: Database Performance

**Risk:** Complex analytics queries slow down with millions of events.

**Mitigation:**
- PostgreSQL indexes on query columns

- Materialized views pre-compute aggregations
- Partition analytics_events by month (old data archived)
- Connection pooling (pgBouncer)
- **Benchmark:** Current queries < 100ms at 100K records

---

### Challenge 3: AI Hallucinations

**Risk:** Gemini might give incorrect study advice (e.g., "learn React in 2 days").

**Mitigation:**
- Structured prompts with validation rules
- Fallback templates for common goals
- User feedback button ("Was this helpful?")
- Human review of AI responses in beta phase
- **Current approach:** Prompts specify "realistic time estimates for Indian students"

---

### Challenge 4: User Adoption

**Risk:** Students might not switch from existing tools (Notion, Google Calendar).

**Mitigation:**
- **Import feature:** One-click import from Google Calendar
- **Export feature:** Export tasks to CSV/Google Cal
- **Freemium model:** Core features free forever
- **Network effects:** Study groups incentivize friends to join
- **Campus ambassadors:** 1 student per college evangelizes

---

### Challenge 5: Mobile Experience

**Risk:** Web-only limits engagement (students use phones more than laptops).

**Mitigation:**
- **Phase 1:** Responsive web design (works on mobile browsers)
- **Phase 2:** Progressive Web App (PWA) with offline mode
- **Phase 3:** Native mobile apps (React Native)
- **Current status:** Fully responsive (tested on 375px width)
